метод calculateMore (возврат сумм) работает быстрее, чем calculateMultiThreadWithLock (общий аккумулятор)

потому что при возврате сумм потоки не конкурируют за общий ресурс, каждый работает со своей локальной переменной и при использовании lock потоки вынуждены ждать друг друга при добавлении в общую сумму, что создаёт накладные расходы

результаты замеров (n=10_000_000, потоки=8):
- однопоточный: 41 мс
- возврат сумм: 19 мс (ускорение 2.10x)
- lock: 21 мс (ускорение 1.94x)

вывод: для параллельных вычислений лучше разбивать задачу на независимые подзадачи и собирать результаты, чем синхронизировать доступ к общему аккумулятору.
