1 вопрос. Builder нужен, когда у объекта много параметров, особенно необязательных. Если делать через конструкторы, получается либо очень длинный конструктор, либо много перегруженных, что неудобно и легко запутаться в порядке параметров.
Builder позволяет создавать объект по шагам и делает код более читаемым. Плюс можно задавать только нужные параметры, не передавая кучу null или значений по умолчанию.

2 вопрос. Мы встречали декоратор в теме работы с потоками ввода-вывода (IO).
Например, в InputStream и BufferedInputStream. Смысл в том, что один поток можно “обернуть” в другой и добавить функциональность, не изменяя исходный класс.

3 вопрос. Adapter используется, когда нужно сделать несовместимые интерфейсы совместимыми. Он как “переходник”. Bridge нужен для разделения абстракции и реализации, чтобы их можно было изменять независимо.
То есть:
Adapter — подгоняет уже существующие классы друг к другу
Bridge — изначально проектирует систему так, чтобы она была гибкой

4 вопрос. Iterator используется в коллекциях.
Например:
интерфейс Iterator
метод iterator() у коллекций (ArrayList, HashSet)
С его помощью можно проходить по элементам, не зная внутренней структуры коллекции

Iterator iterator = list.iterator();
while (iterator.hasNext()) {
    System.out.println(iterator.next());
}

5 вопрос. Шаблонный метод связан с наследованием и полиморфизмом.
Обычно используется в:
абстрактных классах
Протектед или абстрактные методы

Базовый класс задаёт общий алгоритм, а подклассы переопределяют отдельные шаги.

Стратегия связана с композицией и интерфейсами.
Используются в:
интерфейсах
реализациях разных классов с разным поведением

Объект получает стратегию и может менять её во время выполнения.
